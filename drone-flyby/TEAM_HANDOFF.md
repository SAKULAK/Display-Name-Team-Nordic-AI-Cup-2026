## External data and reproducibility

Default teammate capture location: `C:\Users\<USERNAME>\nordicai\drone-captures\`.
Use `$CaptureRoot = Join-Path $HOME 'nordicai\drone-captures'`; do not paste another
person's username. L1 phase folders and metadata are required for projected-label
training. L0 repeat folders are optional and only needed to reproduce the old
offline diagnostic. See [EXTERNAL_DATA.md](EXTERNAL_DATA.md) for full layouts.

Helsinki input is assumed at `datasets/helsinki_multires/` relative to this directory,
with `data.yaml`, `images/train`, `images/val`, `labels/train`, and `labels/val`.
The baseline's saved arguments confirm this dataset. Download that generated dataset
too, or regenerate it using the existing preparation instructions in [YOLO.md](YOLO.md).
The merge preserves its existing assignments. It uses the explicit Helsinki root,
not a stale absolute `path:` from a different computer's generated YAML.

The reproducible validation holdout is **source frames 200..249 inclusive**.
All crops/phases of those frames are val; the rest are train. Missing labels for
entirely unreviewed frames are skipped and reported; partial labeling of a reviewed
frame fails. Duplicate provenance is retained, and a deduplicated image group that
crosses the split causes an error rather than leakage. No random neighboring-frame
split or pseudo-labeling is used. Review audit warnings before training.

Generated datasets/configs contain local paths and stay outside Git. The tracked
template and builders preserve the 16-class order and regenerate portable local
`data.yaml` files. When moving a prebuilt combined dataset, recreate its YAML with
the template and an absolute `path:` for the new machine, or rebuild it. Do not
point training at `validation_yolo/data.yaml`: that is intentionally unsplit.

## Preflight, fresh training, and unattended logging

Use the established `drone-yolo` environment if available. On a new machine, use
Python 3.12 and install `requirements.txt` in your chosen environment; configure
a CUDA-enabled PyTorch installation appropriate for the RTX PC. The preflight checks
module discoverability, not CUDA functionality, and never initializes the GPU.
Use the same Ultralytics/PyTorch versions as the run owner when resuming.

```powershell
conda activate drone-yolo
$CaptureRoot = Join-Path $HOME 'nordicai\drone-captures'
python teammate_preflight.py --capture-root $CaptureRoot
# After following EXTERNAL_DATA.md to prepare the combined dataset:
python teammate_preflight.py --capture-root $CaptureRoot --require-dataset

# FRESH run: starts from the baseline best.pt, with a new optimizer/schedule.
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_validation_finetune.ps1 -CaptureRoot $CaptureRoot -RunName validation_finetune_v1 -Epochs 100 -Batch 4 -Device 0
```

The wrapper refuses an existing fresh run directory, uses the existing training
script defaults (imgsz 960, workers 0 and existing augmentation settings), and logs
to ignored `handoff_logs/<run>_<timestamp>.log`. It does not auto-retry failed runs
or download datasets. `-Python` accepts a Python executable path; `-Data` overrides
the combined dataset YAML. Keep the PC awake and the terminal/session alive;
foreground unattended execution is not a service that survives logout/reboot.

## Resume an existing fine-tune

No `runs/detect/validation_finetune_v1/` directory or existing unattended launcher
was found in the inspected workspace. The launcher supplied here is new; it does
not imply a run has started. If the owner's run exists on another PC, obtain its
run folder from Drive and place it under `runs/detect/validation_finetune_v1/`.

| Artifact | Use |
|---|---|
| `weights/best.pt` | Best validation metric checkpoint for inference or starting a **new** training run |
| `weights/last.pt` | Continue the latest epoch, provided epoch/optimizer state is still present |
| `args.yaml` | Original training parameters and paths; useful for matching environment/configuration |
| `results.csv` | Epoch-by-epoch history and progress; retain with the run |

```powershell
$CaptureRoot = Join-Path $HOME 'nordicai\drone-captures'
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_validation_finetune.ps1 -CaptureRoot $CaptureRoot -RunName validation_finetune_v1 -Resume -Batch 4 -Device 0
```

Resume uses `last.pt`, passes the current machine's `data.yaml` and output run
directory explicitly, and keeps the checkpoint's original schedule. `-Epochs` is
for fresh training only; it does not extend a resumed schedule. Completed/stripped
checkpoints may no longer contain optimizer state, and the helper rejects those
instead of silently restarting training. In that case, start a new named run from
the desired checkpoint via `train_yolo.py --model <best.pt> --data <data.yaml>`.
Resume override support was checked against the locally installed Ultralytics code;
keep the owner's package versions and review startup paths on a different version.

For continuation, share `last.pt`, `best.pt`, `args.yaml`, `results.csv`, dataset
manifests, class configuration and environment versions together. Do not commit a
live checkpoint while training is writing it. Current/new checkpoints should be
downloaded separately; no checkpoint deletion or history migration is required.
